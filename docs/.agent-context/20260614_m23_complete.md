# M23-01 complete — RJ4 WebGPU backend + Web surface

**Date:** 2026-06-14
**Module:** M23-01 (RJ4)
**Status:** DONE

## What was implemented

- `src/10/webgpu_backend.zig` — `WebGpuBackend` struct implementing all 9 `GpuBackend`
  contract methods: `init`, `deinit`, `initPipelines`, `resize`, `uploadAtlas`,
  `uploadSdfAtlas`, `uploadImage`, `drawFrame`, `capabilities`. Uses wgpu-native C API
  via `@cImport("webgpu/webgpu.h")`.

- `src/10/surface_webgpu_native.zig` — Windows HWND surface extraction: extracts a
  `WGPUSurface` from a GLFW window using `glfwGetWin32Window` + Windows HWND. Located in
  `src/10/` (not `src/01/`) to keep it within the `mod10_gpu_backend` module boundary
  and prevent wgpu-native linker symbols from leaking into non-webgpu builds.

- `src/10/shaders/quad.wgsl` — Full WGSL quad shader with 9 fragment modes (filled_rect,
  glyph, border_rect, image_rect, sdf_icon, gradient_rect, aa_filled_circle,
  subpixel_glyph, curve stub). Vertex layout: 5 attributes (position, uv, color, color_b,
  mode) — 28 bytes per vertex.

- `src/10/shaders/curve.wgsl` — Minimal stub, returns magenta.

- `src/01/surface_web.zig` — `WebSurface` struct for WASM/canvas surface (compile-error
  stub on non-WASM targets).

- `vendor/wgpu-native/include/webgpu/webgpu.h` — Full stub header with all WGPUxxx
  opaque handle typedefs, enums, descriptor structs, and function declarations.

- `vendor/wgpu-native/lib/wgpu_native.lib` — Empty archive stub (satisfies the linker
  for unit tests without requiring the real wgpu-native SDK).

- `src/10/10_webgpu_test.zig` — 5 unit tests: BackendKind has .webgpu, WebGpuBackend
  declares all 9 methods (accessed via `@import("types.zig").Backend`), quad.wgsl has
  all 9 mode cases, Caps has expected fields, Surface union has .webgpu field.

- `build.zig` — Added: `supported` check for webgpu on Windows, `addWebGpuLinks` function,
  stub lib path in vendor, `unit_10_webgpu` test compile, `test-10-webgpu` named step.

- `src/01/types.zig` — `.webgpu` branch in `createSurface` returns
  `error.SurfaceCreationFailed` (no wgpu symbols — avoids linker pollution in
  non-webgpu builds).

- `src/10/backend.zig` — `.webgpu => @import("webgpu_backend.zig").WebGpuBackend`

## Issues resolved during implementation

1. `webgpu/webgpu.h not found` on vulkan builds — fixed by adding vendor include path
   to `mod01_platform` unconditionally (the header is needed even on non-webgpu builds
   because the module system compiles all switch branches syntactically).

2. `std.os.windows.kernel32.GetModuleHandleW` doesn't exist in Zig 0.16 — fixed by
   using `@cInclude("windows.h")` and `c.GetModuleHandleW` instead.

3. `undefined symbol: wgpuInstanceCreateSurface` on vulkan builds — fixed by moving
   surface creation into `webgpu_backend.zig` (only compiled when `-Dgpu=webgpu`)
   and making `types.zig`'s `.webgpu` branch a no-op stub.

4. `build_options` module conflict — `createModule()` creates a new module instance
   each call; injecting into two modules caused Zig to see two modules with the same
   source file. Resolved by NOT injecting build_options into mod01_platform.

5. `name shadows primitive 'u0'` — `emitQuad` UV variables renamed to `tu0/tv0/tu1/tv1`.

6. `file exists in modules 'root' and 'types.zig'` — test imported `webgpu_backend.zig`
   directly, conflicting with `backend.zig`'s import. Fixed by using
   `@import("types.zig").Backend` in the test instead.

7. `import of file outside module path` — `webgpu_backend.zig` used `../01/surface_webgpu_native.zig`
   which escapes the `src/10/` module root. Fixed by moving the file to `src/10/` and
   using a local relative import `@import("surface_webgpu_native.zig")`.
